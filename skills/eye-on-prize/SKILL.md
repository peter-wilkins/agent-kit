# Eye On Prize

Keep Continuum moving.

## Trigger

Use this when the conversation starts drifting into:

- process, tooling, or agent-coordination overhead
- elaborate workflow machinery
- repo hygiene that is not blocking current product progress
- speculative architecture not tied to the next useful slice
- debugging the work system instead of building Continuum
- side quests that feel satisfying but do not reduce product risk

## Rule

Before doing the side quest, pause and ask:

```text
Is this really useful for moving Continuum forward right now?
```

Then give one recommended next move.

## Response Shape

Be direct and kind:

1. Name the drift.
2. State the cost.
3. Offer the Continuum-forward alternative.
4. Ask for confirmation only if the user still wants the side quest.

Example:

```text
This feels like coordination machinery, not Continuum progress. It may be worth doing later, but right now it is pulling us away from importing and using real data.

Recommended next move: run the Google Takeout invalid-time issue or inspect the imported cache in the app.

Is this really useful right now, or should I keep us on the data path?
```

## Do Not Overuse

Do not block:

- real user safety/privacy work
- fixes needed to prevent data loss
- short setup needed to unblock the next Continuum slice
- explicit decompression or planning after a tiring session

If the user confirms the side quest matters, do it without nagging.
